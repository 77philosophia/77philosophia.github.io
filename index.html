DDPM

Posted on 2026-08-24 Edited on 2026-08-27 In 专业笔记

来源：2020年Ho et al. introduced Denoising Diffusion Probabilistic Models (DDPMs)

Forward process

\(q(x_0)\)：数据集分布

定义一个前向Markov chain过程： \[ q(x_t | x_{t-1}) \sim N(x_t; \sqrt{1-\beta_t} x_{t-1} , \beta_t I) \\ (\beta_1, ..., \beta_T)是noise schedule \] 根据高斯分布的特性，\(q(x_t | x_0)\)可以表示为： \[ q(x_t | x_0) \sim N(x_t; \sqrt{\bar{\alpha}_t} x_0 , (1-\bar{\alpha}_t) I) \\ \alpha_t = 1-\beta_t \\ \bar{\alpha}_t = \prod_{s=1}^{t}\alpha_t \] 如果\((\beta_1, ..., \beta_T)\)设置合适，最终的\(q(x_T)\)会逼近一个纯高斯变换\(N(0, I)\)

2.从高斯分布 \[ x \sim N(\mu, \sigma^2) \] 采样的过程等价于计算： \[ \sigma * \epsilon + \mu \\其中 \epsilon \sim N(0, 1) \] 因此从\(q(x_t | x_{t-1})\) 或者 \(q(x_t | x_0)\)采样可以直接通过\(x_{t-1}\) or \(x_0\)计算得到，也是由于这个原因前向过程简单，不需要学习。

reverse process

逆向过程就是通过很多步从纯噪声\(x_T\)重建\(x_0\), 我们用\(p(x_{t-1} | x_t)\)表示reverse step of \(q(x_t | x_{t-1})\).

1.第一个关键点就是学习reverse每个去噪步比逆转整个前向过程要简单，也就是学习\(p(x_{t-1} | x_t)\)比直接学习\(p(x_0 | x_T)\)要简单。

但是学习\(p(x_{t-1} | x_t)\)依然很困难，尽管\(q(x_t | x_{t-1})\)是高斯，\(p(x_{t-1} | x_t)\)可以是任何复杂的分布并且几乎绝对不是高斯。从一个任意采样建模和采样肯定比一个参数化的采样比如高斯分布要难。

2.第二个关键点就是前向过程中每步的noise \(\beta_t\)如果足够小，那么逆向步\(p(x_{t-1} | x_t)\)也接近一个高斯分布。因此我们只需要顾及它的均值和方差。实际中，我们设置\(p(x_{t-1} | x_t)\)的方差和前向过程中的\(\beta_t\)。也就是，估计逆向过程的问题可以简化为学习均值\(\mu(x_t, t; \theta)\)， 其中\(\theta\)表示神经网络的参数。

denoising目标

1.传统生成模型的优化目标（最大似然估计）

机器学习中生成模型（比如vae, flow）的目标，是让模型学会真实世界的数据，通过最大似然来实现。调整模型参数theta，来让模型得到真实样本x0的概率p_theta(x0)最大。

对最大似然取负对数，目标就变成了最小化负对数似然。NLL \[ \mathbb{E}[-\log{p_\theta(x_0)}] \] 但是由于公式中隐含的积分或隐变量联合分布，如把图像一步步加噪到纯噪声的全概率展开 \[ p_\theta(x_0) = p(x_T)\prod_{t=1}^T p(x_{t-1} \vert{} x_t) \] ，直接计算这个概率在数学上几乎是不可解的。因此传统模型会去优化它的一个替代指标——变分下界VLB。

2.论文作者 Ho 等人（DDPM 的提出者）通过数学推导发现，在对扩散模型做出特定简化后，那个复杂的变分下界（VLB）最终可以化简为一个极其直观的均方误差（MSE）损失函数。 \[ \mathbb{E}_{t, x_0, \epsilon}\left[ \| \epsilon - \epsilon_\theta (\sqrt{\bar{\alpha}_t}x_0 + \sqrt{1 - \bar{\alpha}_t} \epsilon, t ) \|^2 \right] \]

  • \(x_0\)：原始的干净图像。

  • \(\epsilon\)：标准的正态分布噪声。

  • \[ \sqrt{\bar{\alpha}_t}x_0 + \sqrt{1 - \bar{\alpha}_t} \epsilon \] 这就是前向加噪过程的数学表达式（将干净图像 \(x_0\) 和噪声 \(\epsilon\) 按时间步 \(t\) 的比例混合，得到加噪后的图像 \(x_t\)）。

  • \(\epsilon_\theta(\dots, t)\)：神经网络（如 U-Net），它的任务是输入加噪后的图像 \(x_t\) 和时间步 \(t\)，预测当初加进去的那个噪声 \(\epsilon\)。

训练扩散模型并不需要去算什么复杂的概率，只需要让神经网络去猜噪声，猜得越准（预测噪声与真实噪声的欧氏距离平方最小），模型就学得越好。

因为加噪公式是一个线性的确定性关系（已知加噪图 \(x_t\)、噪声 \(\epsilon\) 和系数，就可以反推出干净图 \(x_0\)），所以预测噪声等价于预测清晰图像。 \[ x_t = \sqrt{\bar{\alpha}_t}x_0 + \sqrt{1 - \bar{\alpha}_t} \epsilon \]

1.正向加噪声

具体的：加噪声： \[ q(xt|x0) = N (xt; \sqrt{\bar{\alpha}_t} x_0,(1 - \bar{\alpha}_t)I) \]

[!NOTE]

在数学和统计学中，概率密度函数（PDF）的标准写法通常是 \(p(x \mid \text{参数})\) 或 \(\mathcal{N}(x; \mu, \Sigma)\)。

这里的第一个参数 \(x_t\) 表示的是随机变量（Random Variable）或当前正在观测/采样的对象，而后面的部分则是这个高斯分布的统计参数（均值和方差）。

  • betas (\(\beta_t\))：噪声方差调度（Variance Schedule）。表示在每个时间步 \(t\) 往图像里注入的噪声强度。通常从一个小值（如 \(10^{-4}\)）随时间线性或余弦递增到一个大值（如 \(0.02\)）。

  • alphas (\(\alpha_t\))：含义：\(\alpha_t = 1 - \beta_t\)。表示在第 \(t\) 步，原始信号（上一时刻图像）保留了多少比例。

  • alphas_cumprod (\(\bar{\alpha}_t\))：

  • 含义：累积阿尔法（Alpha Bar）。\(\bar{\alpha}_t = \prod_{i=1}^{t} \alpha_i = \alpha_1 \alpha_2 \dots \alpha_t\)。

    作用：代表从初始状态 \(x_0\) 经过连续 \(t\) 步加噪后，原图信号一共衰减剩下了多少。它就是前面我们讨论的公式中的核心变量。

得到：

2.知道xt,t,noise可以得到x0或者知道x_t,t,x_start可以知道noise

(diffusion model可以predict原图像或者噪声，都可以) \[ \mathbb{E}_{t, x_0, \epsilon}\left[ \| \epsilon - \epsilon_\theta (\sqrt{\bar{\alpha}_t}x_0 + \sqrt{1 - \bar{\alpha}_t} \epsilon, t ) \|^2 \right] \] 知道噪声 \(\epsilon\) 和 \(x_t\)，求原图 \(x_0\) \[ x_0 = \frac{x_t - \sqrt{1 - \bar{\alpha}_t} \epsilon}{\sqrt{\bar{\alpha}_t}} \] 知道原图 \(x_0\) 和 \(x_t\)，求噪声 \(\epsilon\) \[ \epsilon = \frac{x_t - \sqrt{\bar{\alpha}_t} x_0}{\sqrt{1 - \bar{\alpha}_t}} \]

cfg

生成模型由逼真度和多样性衡量，此消彼长。cfg是手动调控“听话程度（逼真度）”与“丰富程度（多样性）”之间的平衡。

在模型训练过程中：给模型输入条件 \(c\)（例如一段文本描述），但在訓練過程中，會以 10% 到 20% 的概率把这个条件随机抹掉（用空条件 \(\phi\) 代替）。这样一来，模型既学会了“有条件怎么画”，也学会了“没条件时自己盲目发挥會怎麼畫”。

在生成图片的时候会让模型预测两次： \[ 一次是有条件的预测：$\epsilon_\theta(x_t, t, c)一次是无条件的预测：\epsilon_\theta(x_t, t, \phi) \]

\[ {利用这个公式把两个预测结果线性组合起来。} 利用这个公式把两个预测结果线性组合起来 \epsilon_\theta(x_t, t, c) \leftarrow (w+1) \epsilon_\theta(x_t, t, c) - w \epsilon_\theta(x_t, t, \phi) \] w高模型听话w低模型更有创意。

TL:DR

OpenVLA是一个在Open-X embodiment数据集上面训练的97万轨迹上训练的7B模型。重点是开源了。

Methods:

  • Fused visual encoder: 结合
    • DinoV2:一个用自监督方式训练出来的vit模型
    • sigLIP:另一个视觉模型更看重空间推理能力
    • 把两者的特征输出拼接起来
  • Projector
    • 作为一个链接visual encoder和LLM的桥梁，把从visual encoder输出的embeddings转换成兼容的模式。
  • LLM
    • OpenVLA用到的Llama 2(7B)作为backbone.

Results:

该模型在视觉变化（背景、干扰物）、运动变化（物体位置）和语义理解（新指令）方面表现出很强的泛化能力。

RNN的梯度传播：

这种基于时间的连乘的梯度传播的形式会带来两个问题：

由于同一套权重矩阵在时间轴上被反复相乘多次（链式法则），如果权重值偏大，梯度会随着时间步的增加呈指数级增长，导致梯度爆炸（Exploding Gradient）；如果权重偏小，梯度则会呈指数级缩小，导致梯度消失（Vanishing Gradient），让模型无法学到较早时间步的信息。

梯度爆炸可以通过梯度裁剪来解决

梯度消失需要调整rnn结构。

LSTM

定义如下：

LSTM 并没有从数学上彻底根除（eliminate）梯度消失或梯度爆炸问题，但它极大地缓解了这一问题，让网络在实践中更容易学习到长距离的时序依赖关系。

总结：

  • rnn允许在架构设计上有更多的灵活性
  • Vanilla rnns思路很简单但是没有工作很好
  • 更复杂的架构比如lstms,mamba引入了选择性让信息通过的机制
  • rnn里面的梯度反向传播容易vanish或者explode,其中explode的问题可以通过clipping控制，但是随着时间的梯度反向传播总是需要的。

复杂度计算：正比于输入向量的长度N^2,头的个数H

随着输入向量长度的增加，这个复杂度是O(N^2)

Flash attention的复杂度只需要O(N)

注意理解这里的复杂度的概念，其实计算（FLOPS）复杂度还是O(N^2),要算的乘法一个字节都没少；

在 FlashAttention 的语境下指的是显存空间复杂度（Memory Complexity）以及对高带宽内存（HBM）的访存复杂度（I/O Complexity）从 \(O(N^2)\) 降到了 \(O(N)\)。

标准的attention计算，gpu绝大部分的时间和带宽都在每次把结果写入慢速存(HBM)，计算的时候又要读到高速的缓存(SRAM)

对比几种处理sequence的方法：

Rnn:理论上适合处理序列数据，不是并行的，每个cell的hidden state需要顺序更新

Convolution：不适合处理序列数据，但是是并行的。

Self-attention:适合处理序列，也可以并行，但是计算量高

MFU 模型算力利用率

衡量整个大模型训练任务（包括所有前向、反向、优化器及辅助开销在内）最终榨取了硬件理论总算力百分之几的终极指标。

  1. 计算理论浮点运算总数 = 前向传播加反向传播中的矩阵乘法浮点运算总次数，反向传播的计算量通常约为前向传播的 2 倍。忽略非线性激活函数、归一化层、以及诸如残差连接等逐元素操作。它们会在 FP32 核心上运行
  2. 查表获取硬件理论最大吞吐量，例如 H100 为 989 TFLOP/sec
  3. 计算理论所需时间
  4. 测量实际耗时 \(t_{\text{actual}}\)：完成一次完整迭代（包含数据加载、前向、反向、优化器更新）的真实时间
  5. \(\text{MFU} = t_{\text{theoretical}} / t_{\text{actual}}\)（计算 MFU 效率）理论极速时间 / 真实耗时

因为真实耗时（\(t_{\text{actual}}\)）总是大于理论极限时间（\(t_{\text{theoretical}}\)），所以算出来的 MFU 是一个百分比（例如 40% 或 50%）。比例越高，说明你的大模型并行架构和代码工程优化得越好，硬件被压榨得越彻底。

现在会出现的一个情况是：

根据 MLPerf 和多家大厂（如 Google、Meta）披露的数据：

  • A100 训练 175B GPT 类模型，MFU 经常能达到 50% - 55%。
  • H100 训练相同模型，虽然绝对时间变快了（约 2x），但 MFU 往往回落到 40% - 45% 左右。
  • 结论就是：绝对性能（Tokens/秒）是提升的，但能效比和硬件利用率（MFU）确实下降了。因为硬件设计者（NVIDIA）优先选择了堆算力来“刷榜”，而内存带宽的物理提升（HBM3）远慢于晶体管密度带来的算力提升。

原因：

Transformer 架构上。 大模型推理和训练中，除了矩阵乘法，还有大量 “访存密集型”操作，包括：

  • 归一化（Layer Norm）
  • 激活函数（GeLU/SiLU）
  • Dropout
  • 注意力机制中的 Softmax + Mask
  • 所有逐元素操作（Element-wise ops）

这些操作几乎不做计算（FLOPs很低），但需要频繁读写显存（HBM）。

MFU（Model FLOPs Utilization） 衡量的不是“理论峰值跑了多少”，而是“实际有效计算”占理论峰值的百分比。

当算力增长（3.1x）远快于带宽增长（2.1x）时，会发生经典的 “内存墙”效应：

  • 计算密集型任务（大矩阵乘）：算力变强，跑得飞快，耗时极短。
  • 访存密集型任务（小操作）：算力再强也没用，因为数据在 HBM 和 SRAM（片上缓存）之间搬运的速度只快了 2.1 倍。

后果是：在 H100 上，矩阵乘法瞬间算完，但 GPU 不得不“空转”（Stall）等待数据从显存搬过来做下一次归一化。这部分等待时间没有产生任何有效 FLOPs。

H100 为了达到 3.1 倍算力，极大依赖 Tensor Core 和 稀疏性（Sparsity）。

  • 当矩阵维度不够大（比如小批次推理、MoE 模型的小专家网络）时，Tensor Core 的利用率极低。
  • A100 时代，算力没那么高，矩阵乘法刚好能把计算单元喂饱。到了 H100，因为带宽不够快，喂不饱这些更强大的计算单元，“大炮打蚊子”，MFU 自然更难看。

vae

早期两种主流的生成式模型（自回归模型 vs. 变分自编码器）在概率密度建模和优化方法上的根本区别：

  • PixelRNN / PixelCNN（显式密度模型，可直接优化）：它们属于自回归模型。正如前面讨论的，它们利用链式法则将联合概率分解为条件概率的连乘；以直接使用最大似然估计（Maximum Likelihood Estimation, MLE），通过梯度下降去最大化真实图像出现的概率。
  • Variational Autoencoders / VAE（隐变量模型，难以直接计算）
    • VAE 引入了不可见的隐变量（Latent Variables \(z\)）来捕捉图像的底层特征。
    • VAE 的创造者们想出了一种数学技巧：通过引入一个近似后验分布，推导出一个关于对数似然的下界（Lower Bound，通常称为 ELBO - Evidence Lower Bound）。

autoencoder

Autoencoder（自编码器，简称 AE） 是一种无监督的神经网络架构，核心任务是学习输入数据的压缩分布式表示（即隐空间表示，Latent Representation），并尝试尽可能完美地重建原始输入。

  • 标准ae编码器直接输出一个确定的向量；vae输出概率
  • 标准ae的latent space不连续无规则；而vae连续有规律；
  • 标准ae只有重建误差，vae还有kl散度。
  • 标准ae用于压缩降维提取特征等；vae是生成式建模；
  • 标准ae重建的时候直接将z输入decoder, vae使用重参数化技巧。

RSSM的组成

在 RSSM（Recurrent State Space Model，例如在 Dreamer 系列中）中，当我们谈论环境的隐状态（Latent State / Hidden Information）*时，它并不是单一的一个向量，而是由*确定性部分 \(h_t\) 和 随机性部分 \(z_t\)（在部分文献中也记为 \(s_t\)）共同组成的复合状态：

\[s_t = (h_t, z_t)\]

  • 确定性的状态h_t(GRU hidden),用来捕捉暂时的依赖，也就是memory

  • 随机的状态z_t(categorical):捕捉当前状态的不确定性

  • 主要的operations:

    • Observe(): h_t, z_t = f(h_{t-1}, z_{t-1}, a_{t-1}, obs_t) --使用了真实的observation

    • Imagine(): h_t, z^t=f(h{t-1}, z_{t-1}, a_{t-1}). -----no observation(纯想象)，也是dreamerv3的actor-critic工作的部分

训练

actor-critic

dreamerv3会先在world model里面预热几个episodes之后再在actor-ctric框架中训练agent的动作。

我们主要关注actor-critic的逻辑。

Actor(latent) -> action -> imagine_step -> next_latent ->reward

特别注意：actor_loss的计算用的是normalized之后的lambda_Returns值。

正如前面讨论的，传统的无模型强化学习（如 PPO）由于环境不可导，必须使用 Score Function（\(\text{Advantage} \times \nabla \log \pi\)） 来估计梯度。

但在拥有可导世界模型的算法（如 DreamerV3）中：

  • 策略（Actor）的更新往往不直接使用传统的 Score Function，而是直接利用 Pathwise Derivative（路径导数 / 重参数化技巧）。

    1. Score Function 的数学本质：似然比技巧 (Likelihood Ratio Trick)

    • 原理：利用对数导数恒等式 \(\nabla_\theta p_\theta(x) = p_\theta(x) \nabla_\theta \log p_\theta(x)\)。
    • 作用：它允许我们在函数 \(f(x)\) 不可导、未知或者包含黑盒环境的情况下，仅仅通过对概率分布 \(p_\theta(x)\) 进行采样和求对数梯度，就能无偏地估计出期望的梯度。它是无模型强化学习（如 REINFORCE、PPO）和变分推断（如标准的 VAE）的基石。

    2. Pathwise Derivative 的数学本质：重参数化与链式法则 (Reparameterization & Chain Rule)

    • 原理：如果随机变量 \(x\) 可以表示为参数 \(\theta\) 和外部独立噪声 \(\epsilon\) 的可导确定性映射 \(x = g_\theta(\epsilon)\)，那么求导时可以直接穿透期望符号：

      \[\nabla_\theta \mathbb{E}[f(x)] = \mathbb{E}\left[ \frac{\partial f}{\partial x} \frac{\partial g_\theta}{\partial \theta} \right]\]

    • 在世界模型（如 DreamerV3）中的应用：整个世界模型（状态转移方程、观察模型）和策略网络（Actor）共同构成了一个巨大的、参数化的可微计算图。策略生成的动作 \(a_t\) 输入给可微的世界模型得到下一状态 \(s_{t+1}\)，再结合价值函数（Critic），最终的累积回报 \(J\) 对策略参数 \(\theta\) 求导时，不需要做统计意义上的似然比估计，而是直接通过时间轴（Backpropagation Through Time, BPTT）一路反向传播链式法则。

pytorch里的jit加速

Posted on 2026-07-27 In 专业笔记

pytorch with jit

  • 不使用jit:
    • cpu和gpu频繁切换。比如：在具身智能的交互循环中，CPU 需要频繁地把观测数据（Observations）发给 GPU，等 GPU 算完后再把动作（Actions）和奖励（Rewards）传回 CPU。
    • 使用jitting:通过 @torch.jit.script 或 torch.jit.trace，PyTorch 可以把整个模型或核心前向传播过程“编译”成一个独立于 Python 的静态图。这样 GPU 就可以脱离 Python 解释器的逐行控制，大幅减少内核启动开销（Kernel launch overhead），从而提升推理和训练速度。

是不是都可以用jit

  • 动态控制流的限制:对频繁的if/else等动态控制流支持不好
  • 调试困难
  • cpu和io密集型任务不适合

最佳实践

  • 局部优化：只对 Agent 中计算最密集、调用最频繁的神经网络核心模块（例如 policy 推理函数或网络前向传播）使用 @torch.jit.script 或 torch.jit.trace。
  • 先调通，再加速：关闭jit写代码，打开jit大规模并行

经典使用jit的例子

在具身智能和强化学习（例如 Dreamer 算法或在线控制策略）中，最经典、最适合使用 JIT 的模块是 智能体的策略网络前向推理（Policy Forward Pass / Action Sampling Module）

加速原因

  • 摆脱 Python 解释器的逐行调度开销
    • 普通 PyTorch：Python 每执行一行神经网络计算，都要经过 Python 解释器，然后通过 C++ 接口去调用底层 CUDA 算子。如果每一步交互的计算量很小（比如强化学习中单步推理），Python 调度本身消耗的时间甚至会超过 GPU 实际计算的时间。
    • JIT 优化后：整个模型被编译成了一个纯 C++ 层的执行图（Graph），在运行大循环时完全绕过了 Python 解释器，让 GPU 可以连续不断地全速运算。
  • 算子融合（Operator Fusion）
    • 普通 PyTorch：对于 Linear -> ReLU -> Linear 这种常见组合，GPU 通常需要执行三次独立的 Kernel（内核启动）：先算完线性层写回显存，再启动一个 Kernel 做 ReLU，再启动一个 Kernel 做第二个线性层。中间伴随着频繁的显存读写（Memory Bottleneck）。
    • JIT 优化后：编译器会自动将这些相邻的小算子“融合”成一个单一的复合算子（Fused Kernel）。数据直接在 GPU 寄存器/缓存中流转，大幅减少了显存带宽的消耗。
  • 常量折叠与死代码消除（Constant Folding & Dead Code Elimination）
    • JIT 在编译时会预先计算好那些在运行期不会改变的静态表达式（常量折叠），并剔除掉永远不会被执行的分支代码，从而精简最终的计算图。
  • 更好的底层硬件优化：TorchScript 能够以更全局的视角审视整个计算图，产生更优的机器码

理解原生 PyTorch（Eager Mode，即动态图模式）在执行神经网络计算时，Python 代码和底层硬件（GPU/CPU）之间是如何交互的。
