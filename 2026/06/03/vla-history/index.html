vla-history

Posted on 2026-06-03 Edited on 2026-08-17 In 专业笔记

before vla

  • 分层/模块化架构:感知——规划——控制，无泛化
  • 模仿学习：能解决一些复杂的柔性物体抓取，依然受限于“见过的场景”，无法理解人类复杂的自然语言指令。

overview of vla

来自论文https://vla-survey.github.io/data/paper.pdf

各种架构

主要是骨干架构(transformer, vlm) 和动作头(discrete token , diffusion , flow matching)的不同组合。

1.transformer + discrete action

  • 在 VLA 模型的早期阶段（如 RT-1 或 Gato），将 Transformer 用于机器人控制的核心思路是：把机器人的动作（Action）看作是一种“语言”。
  • 自回归生成 (Autoregressive): 模型不是一次性预测出完整的 7 维动作，而是按顺序预测：先预测 \(x\)，再预测 \(y\)，再预测 \(z\)...。这样每一维度的预测都可以参考前面的信息。

2.Transformer + diffusion action head

（diffusion action head结构可以是mlp可以是unet可以是dit）

  • 不对action空间切分，还是连续的。transformer不直接输出动作，而是输出一个环境表征condition,然后送入一个diffusion model进行多部去噪
  • 将机器人控制变成一个条件生成（Conditional Generation）任务，直接建模多峰分布（Multimodal Distribution，即同一个场景下，机械臂既可以从左边绕过去拿杯子，也可以从右边拿）。
  • Ex:Diffusion Policy (TRI团队), π0 (Physical Intelligence), 各种基于 DiT 的具身模型。
  • 动作平滑，解决多峰问题，但是延迟高

3. diffusion transformer

  • 噪声动作直接被转化为 Token，和其他多模态 Token（视觉、语言）一起排队进入 Transformer。
  • 网络主结构它不仅要理解环境，还要直接负责去噪。每一层 Transformer 都在处理“环境特征如何引导噪声还原为动作”。整个 Transformer 骨干网络本身就是去噪器。它利用 Self-Attention 来建模“当前视觉特征”与“正在生成的动作轨迹”之间的复杂空间关系。

vla发展的history line

RT-2 (2023年8月,google mind)——正式提出了vla的概念

将大量的网络数据整合到机器人端到端控制中让机器人操作能涌现出泛化能力URL：

url

官方project url:https://robotics-transformer2.github.io/

Alphaxiv:https://www.alphaxiv.org/overview/2307.15818

Scholarly:https://library.scholarcy.com/try

methods:

  • 预训练的vlm + finetune:互联网规模数据(图像-文本对)+机器人演示数据

    • 为什么有了vlm还要用视觉问答损失？防止忘记通用知识

  • 直接把机器人动作映射为language的同等地位的token，因此架构基本还是vlm的结构。输入是 [256个视觉Token] + [提示词Token]，输出是 [7-8个动作Token]（代表机械臂的 \(x,y,z,\text{roll},\text{pitch},\text{yaw},\text{gripper}\) 离散化 Bin 值）。因为输出序列极短，KV Cache 的压力非常小，核心瓶颈在 Prefill（首字延迟，即视觉 ViT 的前向传播速度）。

  • 推理频率：

    • 55B 旗舰版：在谷歌云端多 TPU 协同下，控制频率仅能达到 1 - 3 Hz（每秒控制 1-3 次），对于高精度、高速率装配来说较为勉强。 5B 剪裁版：控制频率可提升至 5 Hz 左右，基本能满足日常移动抓取任务。
    • 训练 RT-2 采用的是 Co-fine-tuning（共同微调） 策略：70% 的算力喂机器人操作数据（如 RT-1 遗留数据集），30% 的算力继续喂互联网 VQA（视觉问答）数据，防止大模型失忆。

    1.推理频率比较低

    2.展示的demo背景还是很干净的，实际操作估计要翻车。

    根据 DeepMind 发布的论文，RT-2 主要基于两种 VLM 后端（Backbone）构建，形成了三种主流尺寸：

    RT-2 模型变体 后端 VLM 基础 参数量 (Parameters) 架构组成简述
    RT-2-PaLI-X (5B) PaLI-X 小版本 5 Billion (50亿) 较小的视觉编码器 + 轻量级语言解码器，适合高频控制。
    RT-2-PaLM-E (12B) PaLM-E-12B 12 Billion (120亿) ViT (4B) + PaLM-8B 语言模型，具身智能早期经典组合。
    RT-2-PaLI-X (55B) PaLI-X 旗舰版 55 Billion (550亿) 大型 ViT（如 ViT-e 4B+）+ 巨大的多语言 T5 底座，泛化与推理能力最强。

    工业界或学术界在复现/平替 RT-2 时，目前多采用 OpenVLA (7B) 这一开源变体（基于 Prismatic VLM 和 Llama-2-7B 构建）。

OpenVLA——最流行的开源视觉动作语言模型

  • OpenVLA是一个在Open-X embodiment数据集上面训练的97万轨迹上训练的7B模型,基于 Llam、a2、DINOv2 和 SigLIP 构建。

  • 对动作的处理：连续动作值 ∈ [-1, 1] 被均匀分到 256 个 bin 中，离散化后的 bin 索引映射到 LLM 词表末尾的 256 个 token（BPE 词表中最低频的 token），7-DoF 动作 → 7 个 token

[!NOTE]

自回归（Autoregressive）或分类/离散化（Tokenization）的方式来输出动作，即把连续的机器人关节角度或位姿切成离散的 \(bins\)（例如 256 个档位），然后像大语言模型预测下一个词一样逐个预测动作 Token。这种方式虽然能借用大模型的架构，但在处理高频、平滑、多模态（Multimodal，即同一个状态下有多种合理的运动轨迹）的连续物理控制时，往往显得僵硬或精度不足。

而 Diffusion Policy 的核心优势恰恰在于生成连续、平滑、多模态的动作轨迹（Action Chunking），但它本身缺乏强大宏观语义理解和长程推理能力。因此，将两者结合（即 VLA + Diffusion Policy）可以取长补短。

Octo,UC Berkeley——引入基于扩散的生成模型 Diffusion Policy

url:

Diffusion Policy: Visuomotor Policy Learning via Action Diffusion

https://www.alphaxiv.org/abs/2303.04137v5

知识点回顾：

回顾一下diffusion的模型，可以参考()[cs231n-2016.md]

就是从一个噪声起点逐步得到数据分布中的sample的过程，其中可以加condition进行引导。

扩散策略的核心思想是将这一理念应用于机器人动作：它并非直接预测下一个动作，而是从随机噪声出发，根据当前观测结果迭代地将其细化为一个合理的动作（或动作序列）。

但创新远不止于此。 扩散策略不仅仅是预测行为，它还能学习…… 动作分布的梯度 ——即所谓的“评分函数”。它告诉模型，对于任何给定的动作和观察结果，应该朝哪个方向调整动作，使其在已展现行为的分布下更有可能发生。

  • 特点：学习过程比较稳定
  • 克服连续动作多峰分布的问题。
    • 现实世界的示范数据是多模态的（Multimodal）”，而“标准显式策略的数学假设是单峰的（Unimodal）”。
    • 离散的动作没法处理高维，如果不离散连续的动作估计又会出现多峰分布。
  • 扩散策略的一大进步在于它能够预测未来动作的完整序列（action chunk），而不仅仅是下一步动作。（每个时间步，模型能看到全部action_chunk_size长度的动作块，然后进行全局优化，就不像之前观察一步走一步，还容易出现动作之间的割裂）
  • diffusion的网络：1D-cnn或者transformer等
methods:

  • 基于CNN的架构：使用一维时间卷积来处理带噪声的动作序列，并通过特征级线性调制（FiLM）层整合视觉观察和扩散时间步。FiLM机制应用逐元素仿射变换：

    \[ \text{FiLM}(x) = \gamma \odot x + \beta \]

    其中 \(\gamma\) 和 \(\beta\) 是从条件信息中学习得到的。

  • 基于Transformer的架构：将嘈杂的动作序列视为输入标记，由Transformer解码器块处理。视觉观测通过交叉注意力机制整合，使模型能够在预测动作时选择性地关注相关的视觉特征。

  • 滚动时域控制，其中策略预测\(T_p\)个未来动作，但在重新规划前只执行前\(T_a\)步

RDT-1B： DiT

  • Octo 的核心是一个参数量较小（如 Octo-Small 为 27M，Octo-Base 为 93M）的通用 Transformer 主干。它的架构采用“读出标记（Readout Tokens）”机制。在 Octo 的代码配置（如 octo/model/components/action_heads_pt.py）中，动作生成通常被作为一个外挂的下游模块（Readout Head）。你可以通过修改配置自由切换动作头类型：

    这种设计意味着扩散去噪网络并不是主干本身，而是一个挂在主干末端、相对独立的轻量级网络。

  • RDT-1B 整个模型就是围绕 Diffusion Transformer (DiT) 构建的，参数量达到了 1.2B（12亿）。在它的代码中，没有“主干归主干、动作归动作”的割裂感。 * 动作头实现： 噪声动作（Noisy Actions）在代码中直接作为 Token 序列的一部分，与经过编码的视觉、语言、本体状态 Token 一起送入多层 DiT Block（包含 Self-Attention 和 Cross-Attention） 中。整个 1.2B 的大模型直接参与联合去噪，而不是靠一个外部的轻量 Head 去硬画动作。

Flow matching: PI0

url:https://www.alphaxiv.org/abs/2410.24164v1
methods:
  • 视觉-语言骨干网络：基于 PaliGemma，一个预训练的 VLM，用于处理视觉输入和语言指令。该骨干网络利用来自 SigLIP 预训练的 4 亿张图像和来自 Gemma 语言模型的 26 亿个 token。
  • 动作专家：一个专门的模块，将视觉和语言表示转换为机器人动作。该组件在大约 3 亿个参数上进行训练，并使用流匹配来生成适用于机器人控制的连续动作分布。

[!NOTE]

π0 的一项重大创新是使用 flow matching 进行动作生成。现在几乎成了主流。
