机器人策略推理的提速方法

Posted on 2026-09-02 Edited on 2026-09-03 In 专业笔记

异步推理

关键词： grape, server/client架构

以lerobot里的async为例：

独立的客户端/服务端分离架构**，通过 gRPC 通信

*同步推理是串行的*：采观测 → 网络推理 → 机器人空闲等待 → 执行。每个控制周期机器人都要干等一次前向传播。

*异步推理*利用 ACT / pi0 等策略*一次输出整个 action chunk* 的特性，把"执行第 N 块动作"与"用最新观测推理第 N+1 块"在时间上重叠起来，机器人几乎不再等网络。本质上等价于 *MPC 式滚动优化 + ACT 论文的 temporal ensemble（时间集成）*。

RTC

[!IMPORTANT]

论文是 Black、Galliker、Levine 的 《Real-Time Execution of Action Chunking Flow Policies》，2025 年发表于 NeurIPS；它明确把 RTC 定义为一种推理时增强，而不是新的 policy，可以直接作用于 diffusion / flow-based VLA，无需重新训练

RTC（Real-Time Chunking）来自 Physical Intelligence 的论文 "Real-Time Execution of Action Chunking Flow Policies"（Black, Galliker, Levine, 2025, arXiv 2506.07339，见 policies/rtc/README.md）。它不是一种策略，而是 flow-matching 类策略的推理时增强，解决的正是你上一轮问的问题：chunk 边界处因推理延迟产生的机器人停顿和动作跳变——但它在与 temporal ensemble 不同的层面解决（后述）
